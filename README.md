# Deadline Saver

## Proposal Report

### 動機與目標
大學之後發現每天都有不同的任務需要去完成，例如：作業、報告、讀書、社團等等。之前都是使用行事曆來做記錄與安排，但時常不知道該先進行哪一項，也常常不小心忘記某個任務的 loading 其實很重，導致後續任務的時程被擠壓到。所以我想做一個能根據"任務截止日期"與"預估所需時間"去排序的簡易任務規劃的程式。

專題的目標是：

1.建立一個簡易的任務輸入系統

2.根據任務之屬性去做優先排序

3.設計三種策略的排序：依照截止日期、依照所需時間以及各0.5權重的排序方法

4.透過延誤時間評估補同策略的效果

### 競品比較
目前常見的任務管理工具（如待辦事項 App、行事曆）通常提供手動排序、標籤或提醒功能，但較少直接根據任務的截止時間與所需時間，自動計算最佳執行順序。

此專案與其的差異在於：

1.自動化排序：根據輸入的數值進行簡易數學公式計算任務優先度，而非手動設定

2.演算法導向：強調不同排序策略，例如EDF（截止時間優先）、Stress Value（壓力值）、Weighted Score（加權模型）

3.結果分析：透過模擬執行並計算延誤時間，評估策略效果


### 預期功能
會使用到CLI來運作，並且預計加入以下功能：

1.新增任務：包含名稱、截止時間、預估所需時間

2.刪除任務

3.顯示任務列表

4.任務排序（核心功能）：EDF（依截止時間排序）、Stress Value 排序、Weighted Score 排序（可調整權重，預設為0.5）

5.任務執行模擬與評估：根據排序順序依序執行任務、計算每個任務的完成時間、計算延誤時間（delay）

### 使用技術
使用C++作為程式語言，會在CLI執行。資料的處理方式則是使用記憶體中的資料結構。

### Prototype 預計可驗證內容
1.任務資料結構建立（Task struct）

2.基本功能：新增、刪除、顯示任務

3.至少兩種排序方法（EDF + Stress）

4.排序結果顯示

5.任務執行模擬：能依排序結果模擬執行順序，計算各任務完成時間，計算總延誤時間

## Final Report

### 專案說明

#### 動機與目標

大學之後發現每天都有不同的任務需要去完成，例如：作業、報告、讀書、社團等等。之前都是使用行事曆來做記錄與安排，但時常不知道該先進行哪一項，也常常不小心忘記某個任務的 loading 其實很重，導致後續任務的時程被擠壓到。所以我想做一個能根據「任務截止日期」與「預估所需時間」去排序的簡易任務規劃程式。

專題的目標是：

1. 建立一個簡易的任務輸入系統
   
2. 設計三種策略的排序：依照截止日期、依照所需時間以及各 0.5 權重的排序方法

3. 透過模擬執行與延誤時間評估不同策略的效果

4. 針對依截止時間排序這個功能，比較sort、bubble sort 跟 priority queue 在不同資料量下的效能差異

#### 競品比較

目前常見的任務管理工具（如待辦事項 App、行事曆）通常提供手動排序、標籤或提醒功能，但較少直接根據任務的截止時間與所需時間，自動計算最佳執行順序。

此專案與其的差異在於：

   1. 自動化排序：根據輸入的數值進行數學公式計算任務優先度，而非手動設定
   
   2. 演算法導向：強調不同排序策略，包含 EDF（截止時間優先）、Stress Value（壓力值）、Weighted Score（加權模型）
   
   3. 結果分析：透過模擬執行並計算每個任務完成後距截止日的剩餘時間，評估各策略效果並自動推薦最佳方法
   
   4. 演算法效能比較：針對依截止時間排序的功能，比較 std::sort、Bubble Sort、Priority Queue 三種實作在不同資料量下的執行時間

#### 系統功能

1. 任務管理

   使用者可以新增任務（輸入名稱、截止時間、預估所需時間）、刪除任務（根據 ID）、以及顯示所有任務，系統會即時計算並顯示每個任務的剩餘時間與壓力值。

2. 三種排序策略

   Earliest Deadline First（EDF）：依截止時間升序排列，最快到期的任務優先
   
   Sort by Stress Value：壓力值 = 剩餘時間 − 所需時間，值越小代表越緊急
   
   Sort by Weighted Score：結合截止時間與壓力值，使用者可自訂兩者比重，系統自動正規化後計算排序分數

3. 執行模擬與評估

   模擬依三種方法依序執行所有任務的情境，計算每個任務完成後距截止時間剩餘幾小時（Before DL）。若為負值代表該任務將錯過截止日。最終統計各方法錯過幾個截止日，並自動推薦錯過最少的方法，作為使用者選擇策略的依據。

4. 演算法效能比較

   針對「依截止時間排序」這個功能，以三種不同演算法與資料結構實作並比較效能：

   std::sort：STL 內建 introsort，時間複雜度 O(n log n)
   
   Bubble Sort：自行實作，時間複雜度 O(n²)
   
   Priority Queue：使用 std::priority_queue（min-heap），時間複雜度 O(n log n)
   
   在 n = 10、100、1000 三種資料量下，實際測量各演算法執行時間（microseconds）進行比較。

   經過實際測試會發現使用 std::sort 的效率最高。

5. 使用技術

   程式語言：C++17
   
   執行環境：CLI 終端機
   
   主要資料結構：std::vector<Task> 儲存所有任務
   
   排序：std::sort 搭配自訂 bubble sort、std::priority_queue（min-heap）

### 使用方式

1. 環境需求

   g++ 編譯器，支援 C++17（建議版本 7 以上）。Windows 使用者請安裝 MinGW-W64。

2. 編譯方式

   將 main.cpp、task.h、task_manager.h 放在同一個資料夾下，接著執行指令：" g++ -std=c++17 -O2 -o task_scheduler main.cpp " 

3. 執行方式
   
   若使用 Linux 或 macOS，執行指令：" ./task_scheduler "
   
   若使用 Windows，則執行：" .\task_scheduler.exe "

4. 操作說明

   程式啟動後會自動載入 5 筆示範任務並顯示互動式選單，輸入對應數字選擇功能：
   
   選項1：新增任務，依序輸入名稱、截止時間（YYYY-MM-DD HH:MM）、預估時數
   
   選項2：輸入任務 ID 刪除任務
   
   選項3：顯示所有任務及即時計算的剩餘時間與壓力值
   
   選項4：以 EDF 策略排序並顯示建議執行順序
   
   選項5：以壓力值策略排序並顯示建議執行順序
   
   選項6：輸入自訂權重，以加權策略排序
   
   選項7：並列顯示三種排序結果
   
   選項8：執行演算法效能測試，比較 std::sort、Bubble Sort、Priority Queue 三種排序實作在不同 n 的執行時間
   
   選項9：模擬三種方法的執行情境，顯示每個任務完成後距截止日剩餘時間並推薦最佳方法
   
   選項0：離開程式
